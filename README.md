# Интерактивная экосистема молодёжных возможностей Московского района

Первая версия сайта для Московского района Санкт-Петербурга. React + TypeScript + Vite, Leaflet для карты, Three.js + WebXR для виртуального каталога. Работает как статический сайт без серверной части. Подложка Яндекса использует ключ Tiles API; резервная OpenStreetMap работает без ключа.

## Как открыть сайт без терминала

Для просмотра сайта с телефона и компьютера используйте GitHub Pages. Это бесплатный хостинг статического сайта при доступности Pages для вашего репозитория. Публикация облачной среды Codex сохраняет рабочую среду разработки; ссылку на сам сайт создаёт GitHub Pages.

1. Откройте [настройки Pages этого репозитория](https://github.com/leethoof1/MSMRopportunities/settings/pages). В разделе **Build and deployment** найдите **Source** и выберите **GitHub Actions**.
2. Первая версия проекта загружена в ветку `feat/interactive-youth-map`. Если её ещё не перенесли в `main`, откройте [страницу переноса изменений](https://github.com/leethoof1/MSMRopportunities/pull/new/feat/interactive-youth-map), нажмите **Create pull request**, затем **Merge pull request → Confirm merge**. Это добавит файлы сайта в основную ветку `main`.
3. Откройте [вкладку Actions](https://github.com/leethoof1/MSMRopportunities/actions). Дождитесь зелёной галочки у **Publish site to GitHub Pages**. Если запуск ранее завершился ошибкой до включения Pages, откройте этот workflow и нажмите **Run workflow**, выбрав ветку `main`.
4. Вернитесь в **Settings → Pages** и нажмите **Visit site**. Откроется настоящий сайт, где можно нажимать метки и искать занятия. Эту ссылку можно отправить другим людям и открыть на телефоне.

До успешного завершения публикации публичного предпросмотра нет. Если в Actions показан красный крестик, откройте запуск и посмотрите, какой шаг завершился ошибкой.

## Запуск

Требуется Node.js 22.12+ или 24 LTS и npm.

```sh
npm ci
npm run dev
```

Откройте адрес, который покажет Vite. Для проверки готовой сборки:

```sh
npm run build
npm run preview
```

## Что работает

- 22 места: поиск по названию, адресу, занятиям и интересам, направления, карта и список. «Искорка» удалена по уточнению заказчика.
- Карточки со студиями, адресами, временем работы из источника и телефонами; у всех 22 мест есть прямые ссылки ВК, предоставленные заказчиком.
- Смысловой поиск без платных API: «хочу петь» → вокал, «хочу заниматься борьбой» → доступные единоборства, «дроны» → «Простор». Подсказки содержат только реальные занятия и число подходящих клубов. Самбо не предлагается как существующая секция, если его нет в источнике.
- Поиск занятий внутри карточки клуба. Бесплатные занятия для 14–35 лет и платные группы разделены; возрастные условия сохранены там, где указаны.
- Светлая и тёмная тема: по умолчанию следуют настройкам устройства и меняются вместе с ними. На компьютере в шапке три кнопки «Светлая / Тёмная / Авто» для переключения одним нажатием. На телефоне сохранён прежний компактный выбор. Ручной выбор сохраняется локально и применяется до первого отображения страницы.
- Избранное в localStorage; данные никуда не отправляются. Ссылки на выбранное место через `?place=sputnik`.
- Адаптация к телефонам, планшетам и компьютерам.
- При настроенном ключе загружаются изображения официального Yandex Tiles API через Leaflet. Доступны схема, административный и транспортный виды; метки связаны с поиском и карточками. В тёмной теме используется локальное ночное отображение тайлов, без выдуманного параметра API. Старый SDK v3 и нарисованный слой удалены. При ошибках работает резервная OpenStreetMap. [Настройка ключа и проверка настоящего запроса в Actions](docs/yandex-setup.md).
- Виртуальный каталог в WebGL, выбор карточек, страницы и контроллеры WebXR. Отдельный модуль загружается только при открытии VR.

## Данные и ограничения первой версии

Основной новый источник — файл заказчика «Выбери своё направление», сохранённый в `docs/sources/updated-clubs.txt`. Дата публикации не указана. Он обновляет 17 карточек: программы, условия платных групп и контакты. Обновления вынесены в `src/clubUpdates.ts`. Для «Атланта», «Востока» и трёх учреждений «Пулковца», программы которых не перечислены в новом файле, остаётся исходная статья https://vk.ru/@mr.molsovet-podvedomstvennye-uchrezhdeniya от 29.07.2025. Источник обозначен в карточках.

Два учреждения подведомственны администрации района: Молодёжный центр «Московский» курирует клубы, «На Звёздной» и ЦМИ «Простор»; Дом молодёжи «Пулковец» курирует Дом молодёжи, Центр патриотического воспитания и «Просто.Московский». Справочник `organizations` находится в `src/data.ts`.

«Молодёжный» переименован в ЦМИ «Простор», его программы заменены новым списком. Идентификатор `molodezhny` и старое название в поиске сохранены для совместимости ссылок и избранного. «Спутник» не обозначается как офис молодёжного совета. Удалённая «Искорка» не возвращается в каталог: адрес на Алтайской, 37 в новом документе относится к администрации центра. Отделы без отдельных адресов не создаются как самостоятельные точки.

Все прямые ссылки ВК внесены из уточнений пользователя, не получены подбором адресов. «Спутник» — club156414892, «Надежда» — club136795033, «Юность» — club12164429, «Старт» — club139512151. У трёх учреждений «Пулковца» общая группа dmpulkovec. Группа координирующей администрации — zhit_v_moskovskom. Запасной поиск ВК в `vkLinkFor` нужен только для будущих карточек без подтверждённого URL.

Каталог: `src/data.ts`. Адреса и занятия взяты из источников. Подложка — Yandex Tiles API при настроенном ключе либо резервная OpenStreetMap. Координаты, ещё не сопоставленные с адресами, остаются **предварительными**: такие метки имеют пунктирную рамку и подпись об уточнении. Ссылки на Яндекс Карты ищут полный адрес, а не используют предварительные координаты.

Сопоставленные координаты хранятся в `src/geocoded-places.json`. Команда `npm run geocode` (Node.js 24) выполняет однократную проверку адресов через Nominatim с интервалом не меньше 1,1 секунды и сохраняет результаты. Автоматически принимаются только совпадения улицы и номера дома внутри района поиска; несовпавшие адреса требуют ручной проверки. Координата здания не гарантирует положение входа. Повторный запуск использует сохранённые результаты; посетители сайта не вызывают геокодер. Теперь сопоставлены все 22 места: 19 автоматически, ещё 3 после ручной проверки. Для «Романтиков» проверен корпус 2 с литерой А; для «Космоса» совпали название, телефон и группа ВК при отличии записи номера дома. «Октябрь» сверён по карточке Яндекс Карт с точным корпусом и телефоном. Источник и ссылка сохранены у каждой точки; подробности — в [отчёте проверки](docs/geocoding.md).

Для загрузки резервной подложки нужен `tile.openstreetmap.org`, а для повторного геокодирования — `nominatim.openstreetmap.org`. Запросы геокодера в текущей среде выполнены успешно. В браузере посетителя действует его подключение к интернету.

Встроенная карта использует общественный сервер тайлов OpenStreetMap: атрибуция сохранена, предварительной загрузки и массового скачивания нет. Сервер подходит для небольшого проекта, но не предоставляет гарантированной доступности. При росте посещаемости выберите совместимого поставщика тайлов по его условиям.

Бесплатный Конструктор карт Яндекса — отдельный вариант встраивания готовой карты: https://yandex.ru/map-constructor/. В текущем проекте используется Tiles API через Leaflet с фильтрами и карточками; Конструктор не нужен.

Расписание секций, наличие свободных мест, доступность для маломобильных посетителей и актуальность телефонов не проверены. Эти свойства не выдаются за подтверждённые. Расписание «Пулковца» и двух его подразделений предлагается уточнить у организаторов. Общая возрастная группа из статьи — 14–35 лет; условия отдельных студий могут отличаться. Для новых программ стоимость платных групп не выдумывается: посетитель уточняет её у клуба.

Иллюстрации интерьеров — оригинальные векторные рисунки, а не фотографии клубов. Оформление использует розовый и фиолетовый акценты предоставленной карты; официальный брендбук и логотип ещё не предоставлены.

## Панорамы 360° и VR

Панорам пока нет. VR сейчас представляет виртуальный каталог, не экскурсию по реальным интерьерам. Физический шлем в среде не подключён; на устройстве нужно отдельно проверить вход, рендеринг и выбор контроллером.

Для подключения панорамы:

1. Подготовьте эквидистантную панораму 2:1, например JPEG 4096×2048. Убедитесь, что есть права на публикацию фотографий.
2. Положите файл в `public/panoramas/`.
3. Добавьте соответствующему месту поле ``panorama: `${import.meta.env.BASE_URL}panoramas/имя.jpg` ``. При открытии VR из выбранного места модуль отобразит фото внутри сферы.
4. Проверьте панораму в браузере и VR-очках; после добавления она попадёт в фильтр 360°.

Для WebXR необходим HTTPS (или localhost для разработки), совместимый браузер и устройство. Без WebXR трёхмерный каталог остаётся доступным мышью или касанием. Панорамы с несколькими комнатами и переходами между ними — следующий этап.

## Проверки

```sh
npm run build
npm test
```

Playwright проверяет настольный и мобильный Chromium: смысловой поиск и подсказки, отсутствие выдуманных секций, поиск внутри клуба, новые программы и ссылки ВК, системную и ручную темы, фильтры, избранное после перезагрузки, телефонные ссылки, карточки и URL, клики по карте, отсутствие нарисованного слоя, автоматический запрос OSM, отказ и повторную загрузку, а также VR-каталог. В браузерных тестах внешние тайлы намеренно блокируются; это проверяет обработку отказа, а не доступность живого сервиса. Конфигурация облачной среды использует `/usr/bin/chromium`. Для другого расположения задайте `CHROMIUM_PATH=/путь/к/chromium`. При необходимости установите браузер через `npx playwright install chromium` и укажите его исполняемый файл.

## Публикация онлайн

В репозитории подготовлен `.github/workflows/pages.yml` для GitHub Pages. Чтобы получить публичный HTTPS-сайт:

1. Отправьте изменения в ветку `main` репозитория на GitHub.
2. В репозитории откройте Settings → Pages → Build and deployment → Source: **GitHub Actions**.
3. Запустите workflow **Publish site to GitHub Pages** во вкладке Actions (или отправьте новый коммит в main).
4. Дождитесь успешного `deploy`; фактический адрес сайтa будет в результате GitHub Actions и настройках Pages.

Публикация выполняется workflow GitHub Pages после переноса изменений в main; фактический публичный адрес смотрите в Settings → Pages. Workflow требует разрешённого GitHub Pages для репозитория. Перед публикацией сверить координаты и актуальность данных.

Можно также разместить папку `dist` на любом статическом HTTPS-хостинге. Для корня домена используйте `npm run build`; для вложенного пути — `BASE_PATH=/имя-проекта/ npm run build`. Приложение учитывает базовый путь для шрифтов и иллюстраций. Клиентских секретов нет.
