# Яндекс Tiles API

Ключ в этом проекте относится к **Tiles API**, не к JavaScript API v3. Подложка отображается через Leaflet; старый загрузчик v3 удалён. Поиск, метки, карточки клубов и масштабирование работают в нашем коде.

## Ключ и публикация

1. Ключ Tiles API хранится в существующем секрете GitHub **YANDEX_MAPS_API_KEY**. Переименовывать секрет не нужно.
2. Workflow подставляет его при сборке в **VITE_YANDEX_TILES_API_KEY**. После замены значения нужен новый запуск workflow: уже опубликованный JavaScript не читает GitHub secrets во время открытия страницы.
3. Для локальной разработки создайте игнорируемый `.env.local` с `VITE_YANDEX_TILES_API_KEY=...`; шаблон без значения — `.env.example`. После изменения перезапустите Vite.
4. Ограничьте браузерный ключ доменом сайта `leethoof1.github.io`. Ключ технически доступен клиентскому коду; GitHub secret не превращает его в серверный секрет.
5. По документации Яндекса новый ключ может активироваться до 15 минут. Подключение ключа не устанавливает тариф: условия и лимиты определяются в кабинете Яндекса; проект сам не подключает оплату.

## Запрос тайлов

Официальная документация, предоставленная пользователем: https://yandex.ru/maps-api/docs/tiles-api/index.html

Источник: `https://tiles.api-maps.yandex.ru/v1/tiles/`. Передаются `apikey`, `lang=ru_RU`, `x`, `y`, `z`, `l=map`, `scale=1`, `projection=web_mercator`, `maptype`. По умолчанию используется `map`; в интерфейсе также доступны `admin` и `transit`. В API есть и другие виды, но они здесь не запрашиваются.

Важно явно передавать **web_mercator**: Leaflet использует сферический Меркатор, тогда как в Tiles API по умолчанию эллиптический `wgs84_mercator`. Уровни тайлов поддерживаются до 20. Адреса собираются в `src/mapTiles.ts`; показ карты — `src/RasterMapView.tsx`. Проекция не делает предварительные координаты клубов проверенными.

Параметра тёмной темы в предоставленной спецификации нет. Поэтому **ночное отображение выполняется CSS-фильтром только для тайлов**: это не отдельный официальный тёмный стиль Яндекса. Маркеры, подписи интерфейса и атрибуция не фильтруются; переключение темы не вызывает повторной загрузки изображений. Настоящая геометрия карты сохраняется.

Логотип Яндекса и ссылка на текущий участок размещены внизу карты, также сохраняется текстовая атрибуция. Примечания о координатах не закрывают логотип.

## Ошибки и проверка доступности

По документации: 400 — неверные или отсутствующие параметры; 403 — проблема ключа; 429 — слишком много запросов за короткое время. Если изображения не загружаются либо истёк таймаут 15 секунд, сайт переходит на резервную OpenStreetMap с кнопкой «Повторить Яндекс». Каталог остаётся доступен. Событие ошибки изображения не сообщает JavaScript точный HTTP-статус; для этого служат Network браузера и проверка в Actions.

Workflow содержит шаг **Verify Yandex Tiles access**. Он выполняет один запрос тайла с настоящим ключом и реферером сайта, выводит только HTTP-статус и признак изображения. Значение ключа, полный URL и тело ошибки не печатаются. Результат также записывается в сводку запуска. Отказ этой проверки не блокирует выпуск сайта с рабочим резервным вариантом. Доступ из GitHub runner не доказывает доступность из каждой сети посетителя.

`npm run build` и 56 проверок Playwright проверяют сборку и поведение на компьютере и телефоне. В браузерных тестах ответы тайлов явно подменяются: это проверка формата запроса, проекции, интерфейса, ошибок и резервного режима, не утверждение о загрузке живой картографии. Проверка положительного и отрицательных путей скрипта Actions также выполнена с локальными ответами. Настоящий ключ находится у пользователя в GitHub; реальная проверка сервиса выполняется после слияния в workflow и в браузере.

Предоставленная документация и тесты не содержат значения пользовательского ключа. Демонстрационный ключ из примера документации не используется.
